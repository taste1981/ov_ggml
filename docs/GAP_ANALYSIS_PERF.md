# Gap analysis: Issues found during OpenVINO GGUF performance testing (2026-11-19)

**Overview: 11 findings, 3 fixed, 8 open.**

This document records issues uncovered during OpenVINO GGUF performance testing in `llama-work-note`, including correctness and compatibility issues. It excludes issues already documented in the [main gap analysis](GAP_ANALYSIS.md). Finding IDs are local to this document. `ovfe` denotes the OpenVINO GGUF frontend, not the GGML device.

Severity, as in the main review: **P0** wrong results or memory corruption; **P1** blocks a realistic use case, or a major gap; **P2** robustness, performance or process; **P3** hygiene.

## 1. Fixed since the review

| Problem | Effect | Fix | Where |
| :-- | :-- | :-- | :-- |
| 1: The graph dumper increased `n_batch` but left `n_ubatch` at the default of 512 | llama.cpp split the 1024-token capture into two 512-token microbatches. The dumper wrote nodes from both graphs into one artifact instead of exporting a single 1024-token graph. This also happened on a CPU-only build. | Set `n_ubatch` to at least the requested token count so the capture fits in one microbatch | [ggml-cgraph-generator #5](https://github.com/ynimmaga/ggml-cgraph-generator/pull/5); verified with local generator commit `09420ff` |
| 2: GenAI's GGUF tokenizer ignored `tokenizer.ggml.add_bos_token=true` | GenAI sent a plain-text prompt to Gemma-4 12B without its beginning-of-sequence (BOS) token. The model generated repeated digits rather than answering the prompt. | Prepend the BOS token ID with `CombineSegments` when GGUF metadata requests it. Locally, the prompt token count matched llama.cpp and the repeated digits disappeared. | Upstream GenAI `d929736c`, integrated locally in `712b5617`; branch update: [ynimmaga/openvino.genai #2](https://github.com/ynimmaga/openvino.genai/pull/2) |
| 3: `ovfe` treated KV slot indices as token positions when building the causal mask | NPUW pads the static prefill window on the left. The slot indices of real tokens therefore differ from their sequence positions, and the mask could hide tokens that should have been visible. Qwen3-4B and Llama-3.2-1B produced garbled text. | Derive key positions from `CumSum(attention_mask) - 1` and exclude padded slots. The tested NPU outputs matched CPU outputs without the local workaround. | Upstream OpenVINO `630516e048` (#38358), in `adapt_to_genai.cpp`; branch update: [ynimmaga/openvino #108](https://github.com/ynimmaga/openvino/pull/108) |

## 2. New gaps found by testing

| ID | Area | Gap | Evidence | Suggested fix | Sev |
| :-- | :-- | :-- | :-- | :-- | :-: |
| 4 | NPU | On Intel AI Boost NPU 3720, TinyLlama-1.1B takes longer to process the prompt and generate each token via `ovfe` than via OpenVINO IR. | The paths use different weight representations. Controlled changes implicated group-32 layer weights in prefill and the grouped Q6_K output projection (LM head) in decode, but did not explain the entire difference. | Inspect NPUW decompression pattern matching for Q6_K and Q8_0; test per-channel `Q8_0_C` for the LM head. | P1 |
| 5 | Prefill | If the only configured prefill bucket is large, the GGML device runs its full fixed-size graph even for a short prompt. | Short prompts ran through the 1024-row artifact, doing work for padded rows. This increases the time to the first token; it is not the recurrent-model restriction on padding. | Include smaller buckets in default configurations and verify that the runner selects the smallest bucket that fits the prompt chunk. | P2 |
| 6 | NPU | The tested Qwen3-4B Q4_K GGUF did not reach inference on NPU37XX via `ovfe`. | The driver-compiler run was cancelled before it finished. The plugin compiler explicitly rejected the asymmetric u4 `DequantizeOp`. Requantizing to Q4_0 bypassed this compilation failure. | Check whether the frontend can convert the weights to a representation supported by NPU37XX, or report the unsupported format before compilation. | P1 |
| 7 | NPU | With the shared LM head enabled, NPUW can fail to partition a GGUF graph before inference starts. | For Llama-3.2-1B, the partitioner could not find the `logits` MatMul that uses `token_embd.weight` as its weights. Setting `NPUW_LLM_SHARED_HEAD=NO` bypassed the failure but did not fix the shared-head path. | Check how the partitioner identifies the LM head when it shares weights with the token embedding. | P1 |
| 8 | GPU | `ovfe` sometimes produced garbled output on an Intel iGPU, including with short prompts. | Identical short prompts and settings gave normal text in one run and garbled text in another. Longer prompts also produced garbled text. The tests did not isolate whether the frontend or the GPU plugin caused the failure. | Repeat with identical input token IDs and compare first-step logits across GPU runs and against the CPU path. | P0 |
| 9 | llama.cpp | The llama.cpp OpenVINO backend produced malformed or repeated text for a Gemma-4 12B prompt longer than its sliding attention window. | On the same long-prompt case, the separate GGML-device SWA fix restored normal text, but the llama.cpp OpenVINO backend still produced bad output. The cause in that backend is unconfirmed. | Reproduce on the same token IDs and use llama.cpp Vulkan as a reference to find the first divergent decode step. | P0 |
| 10 | NPU | Disabling NPUW's shared LM head can make OpenVINO IR inference fail with an output shape mismatch. | With `NPUW_LLM_SHARED_HEAD=NO`, TinyLlama IR produced logits for all prefill rows, but the declared output expected logits for a single token. The runtime rejected the result. | Check which NPUW graph transformation should select the last token when the LM head is not shared. | P2 |
| 11 | Quantization | The tested `ovfe` Q4_K conversion lost precision by storing the weight zero point as an unsigned 8-bit integer. | Qwen3-4B generated a different first token from llama.cpp despite identical prompt IDs. Preserving the zero point as f16 via `OV_GGUF_Q4_K_ZP_F16=1` made the tested CPU output match, but did not change the default conversion. | Retest the current default conversion and compare CPU logits with and without the f16 option. | P2 |
